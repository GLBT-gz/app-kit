# 框架接入指南（新项目从模板复制后必须做的事）

> **本文件是 AI 接手的硬性骨架。** 任何从 `000-基础模板` 复制的新项目，按本指南 6 步走完才能跑通紫鸟等业务能力。漏步骤必踩坑（typecheck 红 / 运行时缺按钮 / 店名不显示）。
>
> **同步入口**：`glbt-apps/docs/新AI上手.md` 第3节是本文件的速查版（少细节）；本文是完整版。

---

## 0. 复制模板

```powershell
xcopy /E /I "glbt-apps\projects\000-基础模板" "glbt-apps\projects\XXX-你的项目名"
Remove-Item -Recurse -Force "glbt-apps\projects\XXX-你的项目名\node_modules", "glbt-apps\projects\XXX-你的项目名\dist"
```

> ⚠️ **不要复制 008/015/016 等已配置紫鸟的项目当模板** —— 它们带了业务面板和设置项。先复制 `000-基础模板`，再按本文接入。

---

## 1. 前端 — `package.json`

`dependencies` 加 `@glbt/ui`（workspace 链接，无需指定版本）：

```json
{
  "dependencies": {
    "@appkit/ui": "file:../../../app-kit/shared/ui",
    "@glbt/ui":  "workspace:*",
    "@tauri-apps/api": "^2.11.1",
    "@tauri-apps/plugin-dialog": "^2.7.1",
    "@tauri-apps/plugin-process": "^2.3.1",
    "react": "^19.2.7",
    "react-dom": "^19.2.7"
  }
}
```

**判断原则**：项目是否会用到 `ShopCachePanel` / 紫鸟 Profile / 紫鸟相关 UI 扩展？会 → 加；不会 → 不加（纯数据项目如 005 可不加）。

跑 `pnpm install`。

---

## 2. 前端 — `src/main.tsx`

**调 `registerZiniaoFramework()` 一站式注册**（@glbt/ui 提供，幂等）：

```tsx
// src/main.tsx（最小骨架）
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";

import App from "./App.tsx";
import "@glbt/ui/styles";
import { registerZiniaoFramework } from "@glbt/ui";

// 紫鸟业务扩展注册（数据项 + 浏览器列表后处理 + 浏览器启停适配器 + UI 扩展）
registerZiniaoFramework();

createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <App />
  </StrictMode>,
);
```

### 它注册了什么（缺一项必出问题）

| 序号 | 注册项 | 出错症状（不调） |
|---|---|---|
| 1 | `core-ziniao-env-map` 数据项（localStorage 注册） | localStorage 写入店名映射失败 |
| 2 | `applyZiniaoEnvNames` 浏览器列表后处理钩子 | 紫鸟 Profile 显示 `环境 12345`，真实店名不显示 |
| 3 | 紫鸟浏览器启停 / 调试启动适配器 | `launchProfileSmart("ziniao", ...)` 找不到实现 |
| 4 | `registerZiniaoUIExtension()`（UI 扩展 + 「登录并绑定店铺名称」按钮） | 「全局浏览器配置」紫鸟展开项没有绑定按钮、头像非圆角形状 |

> **历史错误**：早期 000 模板只调单项 `registerZiniaoUIExtension()`，缺第 2 项 transform，导致店名绑定后 UI 不刷新。一站式函数杜绝部分注册。

### ⚠️ 何时不调

纯数据项目（不引 `@glbt/ui`）自然也不调。但若引用了 `ShopCachePanel`（在 `@glbt/ui` 里），仍要调 + 加 CSS 声明。

## 3. 前端 — `src/vite-env.d.ts`

**必须加 `@glbt/ui/styles` 模块声明**，否则 typecheck 报：

```
src/main.tsx(5,8): error TS2882: Cannot find module or type declarations
for side-effect import of '@glbt/ui/styles'.
```

最小骨架：

```ts
/// <reference types="vite/client" />

declare module "*.css" {}

// @glbt/ui 的样式子路径导出（./styles → ziniao.css）
declare module "@glbt/ui/styles";
```

> 这一行是 008 / 015 / 016 都自带、000 模板**缺失**的小配置。复制模板时必须补。

---

## 4. 前端 — `src/App.tsx`

模板已自带最小 `registerPlatforms([])` 占位调用：

```tsx
// 基础模板：无具体业务平台，预留 registerPlatforms 调用位置
registerPlatforms([]);
```

业务项目按需传平台列表（如 008 的跨境店铺）：

```tsx
registerPlatforms([
  { key: "cross01", label: "跨境01" },
  { key: "cross02", label: "跨境02" },
]);
```

## 5. 后端 — `src-tauri/Cargo.toml`

如果项目要用紫鸟 agent / patch / CDP 管理命令，必须启用紫鸟 plugin feature：

```toml
[dependencies]
appkit-core = { path = "../../../../app-kit/shared/core", features = ["bridge", "cmd-full"] }
# 可选：紫鸟 + 易得客检测器 + 命令插件
platform-ziniao = { path = "../../../platforms/ziniao", features = ["plugin"] }
platform-edecker = { path = "../../../platforms/edecker" }
```

> ⚠️ **不要**漏 `features = ["plugin"]` —— 没开这个 feature，`platform_ziniao::plugin::commands()` 函数根本不存在，编译失败。

---

## 6. 后端 — `src-tauri/src/lib.rs`

### 6.1 注册浏览器 detector

```rust
.setup(|app| {
    // 注册专用浏览器检测器（紫鸟 / 易得客），使「全局/当前浏览器配置」面板可检测展示
    platform_ziniao::registry::register();
    platform_edecker::registry::register();
    // ...
    Ok(())
})
```

不调 → `detect_browsers` 命令**不会返回紫鸟 / 易得客**，前端全局浏览器配置面板看不到它们。

### 6.2 注册紫鸟命令插件

```rust
.invoke_handler(platform_ziniao::plugin::commands())  // 33 条紫鸟命令
```

不调 → 前端 `invoke("plugin:ziniao|ziniao_agent_launch")` 全部 `not found`。

> **坑点**：Tauri 2 的 `Builder::invoke_handler` 接受 `Box<InvokeHandler<Wry>>`，**多次调用会替换**（不是合并）。`appkit-core` 的命令已经在 `tauri_bridge.rs::init()` 通过 `.plugin(...)` 注册；紫鸟命令是单独的 `.invoke_handler(...)`。两者并存，**第二个会替换第一个**。
>
> 正确做法：appkit-core 用 `.plugin(...)`、紫鸟用 `.invoke_handler(...)` —— 因为它们走的是不同注册路径，**不会互相覆盖**。但**项目自身命令**（如 `open_directory`）必须在 `generate_handler!` 里和紫鸟命令合并，不能单独再写一次 `.invoke_handler(generate_handler![...])`。

## 7. 验证清单（复制模板后必跑）

```bash
cd glbt-apps/projects/XXX-你的项目名
pnpm install             # 必须 0 错
pnpm typecheck           # 必须 0 错（@glbt/ui 包内部的 sourceBusy 未用变量警告可忽略）
pnpm run tauri dev       # 窗口能打开 → 进「全局浏览器配置」能看到紫鸟 / 易得客 → 紫鸟展开项有「登录并绑定店铺名称」按钮
```

如果 **typecheck 挂**：

- `Cannot find module '@glbt/ui/styles'` → 漏第 3 步 `vite-env.d.ts`
- `registerZiniaoFramework is not exported` → 漏第 1 步 `package.json` 加依赖
- `erasableSyntaxOnly` 相关错误 → 删 `tsconfig.app.json` 的 `"erasableSyntaxOnly": true`

如果 **运行时紫鸟缺失**：

- 「全局浏览器配置」看不到紫鸟 → 漏第 6.1 步 detector 注册
- 紫鸟展开项没「登录并绑定店铺名称」按钮 → 漏第 2 步 `registerZiniaoFramework()`，或只调了单项 `registerZiniaoUIExtension()`
- 店名绑定后 UI 仍显示「环境 12345」→ `registerZiniaoFramework()` 内部第 2 项 `applyZiniaoEnvNames` 没生效（通常意味着调用了但未引入 `core-ziniao-env-map` 数据项 / 或数据未写入 localStorage）

## 8. 反模式（不要这样做）

| 反模式 | 后果 |
|---|---|
| 只调 `registerZiniaoUIExtension()`（单项） | 缺 transform，店名不显示 |
| 调 `registerZiniaoFramework()` 但忘 `import "@glbt/ui/styles"` | 紫鸟卡片无样式 |
| `vite-env.d.ts` 漏 `declare module "@glbt/ui/styles"` | typecheck 红 |
| 复制 008 当模板而不是 000 | 继承了一堆业务侧设置项 + 跨境店铺平台 + ZiniaoTestPanel，需手动清理 |
| `Cargo.toml` 加 `platform-ziniao` 但漏 `features = ["plugin"]` | 编译报 `cannot find function 'commands'` |
| `.setup` 块忘 `platform_ziniao::registry::register()` | 前端检测不到紫鸟 |
| `.invoke_handler` 漏 `platform_ziniao::plugin::commands()` | 紫鸟命令全部 not found |
| **复制模板后**漏 `pnpm install` | typecheck 找不到 `@glbt/ui` 模块 |

## 9. 参考实现

- **业务项目标杆**：`008-紫鸟运营工具` —— 完整紫鸟接入 + 业务面板
- **轻量项目标杆**：`015-自动回复` —— 接入紫鸟但不开跨境
- **纯数据项目标杆**：`005-产品开发单品毛利计算` —— 不引 `@glbt/ui`

复制模板后**先看这三个标杆的 `main.tsx` / `vite-env.d.ts` / `Cargo.toml` / `lib.rs`**，对照骨架 6 步差什么再补。

## 附录：本指南的来源

2026-09 期间 000 模板对接紫鸟时反复试错 5 轮才理清：
1. 漏 `@glbt/ui` 依赖（pnpm install 不带它）
2. 错把 `registerZiniaoUIExtension()` 当成完整注册（实际是 4 项里的 1 项）
3. 漏 `import "@glbt/ui/styles"` 导致紫鸟卡片无样式
4. 漏 `declare module "@glbt/ui/styles"` 导致 typecheck 红
5. 误以为 `erasableSyntaxOnly` 是必须的（实际可删）

这次把每步的「必做」「漏做症状」「反模式」都收口在本文件。**之后任何新项目从 000 复制，6 步走完不再返工。**
