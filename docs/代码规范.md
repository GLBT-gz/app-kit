# 代码规范

> **速读卡（AI 必读）**：
> ① 提交格式 `<type>(<scope>): 中文`（type: feat/fix/chore/refactor/docs；scope: 项目编号或 shared 模块）；
> ② Rust 用 snake_case / PascalCase，TS 组件 PascalCase、文件 kebab-case；
> ③ **禁止硬编码颜色**，一律用主题变量 `var(--bg-*)`/`var(--text-*)`/`var(--accent)`（详见「主题与颜色」节）；
> ④ 版本号必须 `env!("CARGO_PKG_VERSION")`，禁止硬编码；版本号三处一致；
> ⑤ 标签滚轮切换要**穿透到副容器**：事件绑在整个顶栏/外层容器，不绑在标签栏自身（详见「滚轮交互规范」节）；
> ⑥ **开发端口 = `5170 + 编号`**（模板/000=5170、001=5171…007=5177、010=5180、999=6169），`vite.config.ts` 的 `port` 必须按此设置。

## 提交规范

```
<type>(<scope>): <简短描述>

<详细说明（可选）>
```

> **说明：** `<简短描述>` 和 `<详细说明>` **必须使用中文**，禁止使用英文。scope 和 type 保持英文小写。

**类型（type）：**

| 类型 | 说明 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复 |
| `chore` | 杂项（配置、版本号等） |
| `refactor` | 重构 |
| `docs` | 文档 |

**作用域（scope）——支持组合：**

| scope | 说明 |
|-------|------|
| 数字编号（如 `000`、`001`） | 对应下游仓库的项目编号 |
| `shared/ui` | 共享前端组件/样式/Hooks |
| `shared/core` | 共享 Rust 核心库 |
| `shared/automation` | 共享浏览器自动化层 |
| `releases` | 版本发布配置/脚本 |
| `docs` | 文档 |
| `*` | 跨多个模块的全局改动（极少使用） |

当一次提交同时涉及项目代码和共享库时，使用 `+` 连接多个 scope：

```text
fix(003 + shared/ui): 修复备货量表单提交后 UI 不刷新
feat(001 + shared/automation): 采购单自动提交功能
```

## Rust 命名规范

| 类型 | 规范 | 示例 |
|------|------|------|
| 类型/结构体/enum | `PascalCase` | `BrowserConfig`, `DetectResult` |
| 函数/方法 | `snake_case` | `detect_browsers()`, `launch_browser()` |
| 变量/常量 | `snake_case` | `chrome_path`, `max_retry_count` |
| 模块名 | `snake_case` | `mod browser;` |
| Cargo feature | `kebab-case` | `cmd-browser`, `cmd-full` |

### API 反序列化字段命名

从外部 API 反序列化的结构体字段，虽然 JSON 返回的是 `camelCase`，但 Rust 侧**必须使用 `snake_case`**，通过 `#[serde(rename = "...")]` 映射到 JSON 字段名：

```rust
// ✅ 正确：Rust 字段用 snake_case，通过 serde(rename) 映射到 JSON 字段
#[derive(Deserialize)]
struct InventoryRow {
    #[serde(default)]
    #[serde(rename = "warehouseSku")]
    pub warehouse_sku: String,
    #[serde(default)]
    #[serde(rename = "qtyTotal")]
    pub qty_total: i64,
}

// ❌ 错误：Rust 字段用了 camelCase，违反命名规范
#[derive(Deserialize)]
struct InventoryRow {
    pub warehouseSku: String,   // non_snake_case 警告
    pub qtyTotal: i64,          // non_snake_case 警告
}
```

### 版本号管理

`get_app_version()` 命令**必须使用 `env!("CARGO_PKG_VERSION")`** 自动从 `Cargo.toml` 读取版本号，禁止硬编码：

```rust
// ✅ 正确：自动同步 Cargo.toml 中的版本
fn get_app_version() -> String {
    env!("CARGO_PKG_VERSION").to_string()
}

// ❌ 错误：硬编码字符串，容易忘记同步更新
fn get_app_version() -> String {
    "0.1.0".to_string()
}
```

## 站点 JS 资产归属（分层架构）

**页面 DOM 操作、注入 JS、站点选择器一律归 Rust 平台层，前端禁止持有站点 JS 资产。**

分层模型（由底到顶）：

| 层 | 位置 | 职责 | 允许内容 |
|----|------|------|---------|
| CDP 原语层 | `appkit/shared/automation` | 只提供「执行 JS 的通道」（`runtime_evaluate`/`input_click`/`page_navigate`） | 不含任何站点选择器 |
| 站点知识层 | `platforms/*`（Rust crate，位于下游仓库） | 内嵌 `r#"JS"#` 原始字符串（选择器/注入 JS/业务流程），如某站点的侧边栏解析与切换 | 站点选择器、页面操作逻辑 |
| 命令层 | `projects/*/src-tauri/*.rs` | Tauri 命令：薄封装 + 编排（浏览器启动/进度事件/取消） | 不含页面 JS |

**消费应用前端（`projects/*` 的 src）只做 UI 编排**，通过语义化参数（如 `port` + `query`）调用 Rust 命令，禁止直接写页面 JS 或持有站点选择器。

> 反例（已修正）：框架 UI 层曾有一个站点模块在前端持有 8 段注入 JS 和 10+ 个站点选择器、绕过平台层直调底层 eval 命令，已于 2026-08-16 退役，逻辑并入下游对应的 `platforms/*` crate（精准选择器 + 语义兜底双策略）。
>
> 历史欠账（需逐步迁移）：部分下游项目仍在命令层内联站点 JS（无对应 `platform-*` crate）——新代码禁止沿用此模式。

## CSS 规范

**页面边距规范（必须遵守，防止边距反复出错）：**

页面边距由三层容器语义决定（定义见 `shared/ui/src/styles/base.css` 顶部注释）：

| 页面类型 | 正确做法 | 禁止做法 |
|---------|---------|---------|
| 普通页（首页/表单页等需要默认边距） | 根节点挂 `.page-padded`（12px 20px）或 `.main-content`（24px） | — |
| 全屏页（自动化页/测试页/层叠标签页） | 根节点**不加任何边距类**，页面组件自带布局 | 挂 `.main-content`（其自带 24px padding，去掉它需在项目 CSS 写 `:has()` 反覆盖——依赖共享组件内部 DOM 结构，极其脆弱，已导致 002/003/005/006/007/013 反复出问题） |
| 设置面板 tab 内容 | 内容组件**必须自带 padding**（`.settings-content` 容器无 padding） | 直接放不带边距的组件（内容会贴边） |

设置页组件 padding 现状清单：
- 自带边距：`DataManagerPanel`（.dm-panel）、`ShortcutsPanel`（.settings-section）、`BrowserConfigPanel`（.panel-content）、`CredentialsForm`（传 `padded` prop）
- 不自带边距：`AutomationSettings`（其内部用内联 `padding: 0 28px` 包裹 children，CredentialsForm 嵌入其中时**不要**再传 `padded`，会双重边距）

新增设置页组件时一律自带 padding；新增全屏页组件时根节点不要依赖任何页面容器类。

**CSS 方案：** 以手写 CSS（`*.css` 文件）为主。共享 UI 的 `createViteConfig` 内置 Tailwind PostCSS 工具链（默认开启、preflight 已禁用，仅作工具链使用）；业务项目不需要时可传 `enableTailwind: false` 关闭（001/002/004 已关闭），业务样式应使用手写 CSS，不建议依赖 Tailwind 原子类。

**全局字体：** 已在 `shared/ui/src/styles/theme.css` 的 `:root` 中定义（`index.css` 仅做 `@import` 汇总），所有 UI 文本应继承此字体。

```css
font-family: "Maple Mono", -apple-system, BlinkMacSystemFont, "Segoe UI",
    "PingFang SC", "Microsoft YaHei", sans-serif;
```

- 只有以下情况可以使用等宽字体（`var(--font-mono)`）：
  - 命令展示（`.cmd-box`、`.cmd-inline`、`.cmd-arg`）
  - 代码/路径/ID 信息（`<code>` 标签）
  - 快捷键按键（`<kbd>` 标签）
  - 颜色值（`.skin-hue-value`）
- **不要给普通文本元素**（版本号、按钮文字、标签等）设置 `font-family`，让它们继承全局字体。

### 主题与颜色（必须遵守）

**主题机制：** 明暗主题由 `data-theme` 属性切换（顶栏主题按钮），深浅两套变量定义在 `shared/ui/src/styles/theme.css`。**所有 UI 必须使用主题变量，禁止硬编码颜色值**——硬编码会破坏深浅主题适配和调色板主题色。

```css
/* ❌ 禁止：硬编码颜色，深浅主题下表现异常 */
.btn { background: #ffffff; color: #000000; }
.input { border: 1px solid #e0e0e0; }

/* ✅ 必须：使用主题变量，自动适配深浅主题 */
.btn { background: var(--accent); color: var(--btn-text); }
.input { background: var(--bg-input); border: 1px solid var(--border-input); }
```

**主题变量速查：**

| 用途 | 变量 |
|------|------|
| 页面背景 | `var(--bg-app)`、`var(--bg-content)` |
| 卡片/面板 | `var(--bg-card)`、`var(--bg-card-hover)`、`var(--bg-surface)`、`var(--bg-modal)` |
| 输入框/表单 | `var(--bg-input)`、`var(--border-input)`、`var(--border-input-focus)` |
| 分隔/描边 | `var(--border)` |
| 主文字 | `var(--text-primary)` |
| 次要文字 | `var(--text-secondary)` |
| 弱化文字/占位 | `var(--text-muted)` |
| 强调色（主题色/调色板） | `var(--accent)`、`var(--accent-hover)`、`var(--accent-light)` |
| 成功/错误 | `var(--success)`、`var(--error)` |
| 按钮文字 | `var(--btn-text)` |
| 阴影 | `var(--shadow)` |

**强调色（主题色）：** 按钮主色、选中态、链接、聚焦光环一律用 `var(--accent)` 系列，不写死品牌色/蓝色。调色板设置动态改变 `--accent`：

```css
.btn-primary { background: var(--accent); color: var(--btn-text); }
.btn-primary:hover { background: var(--accent-hover); }
.item-selected { background: var(--accent-light); color: var(--accent); }
a { color: var(--accent); }
```

**验收清单（写完样式自查）：**
- [ ] 无硬编码颜色（`#fff`/`#000`/`white`/`black`/`#f0f0f0` 等）
- [ ] 按钮/输入框/下拉框用 `--bg-*`、`--border-*`、`--text-*` 变量
- [ ] 主色/选中/链接用 `var(--accent)` 系列
- [ ] 深浅两种主题下 UI 均正常（切换顶栏主题按钮验证）

### 滚轮交互规范（标签切换穿透到副容器）

**标签页栏的滚轮切换，事件必须绑在整个副容器（顶栏/外层容器）上生效，不能只绑在标签项或标签栏自身宽度上**——标签只有 2-3 个时，整个容器区域滚动都应能切换标签。

**主顶栏（AppLayout/TopBar，共享层已实现）：**
- 滚轮监听由共享层挂在整个 TopBar 容器（[TopBar.tsx](TopBar.tsx) 原生 `wheel` 监听），通过 `onTopBarWheel` prop 提供给项目。
- **TabBar 自身不监听滚轮**（TabBar.tsx 注释：「滚轮切换由父组件通过 onWheel 决定范围」）。
- 项目侧正确用法：`handleTopBarWheel = tabWheelHandler(activeTab, setActiveTab)` 传给 AppLayout（下游项目在自身 `src/types.ts` 中实现 `tabWheelHandler`）。

**自定义标签栏（测试页/设置面板等）：用共享 hook `useWheelTabSwitch`（@appkit/ui 导出）**

```tsx
const containerRef = useRef<HTMLDivElement>(null); // ref 指向覆盖整个栏目范围的外层容器（副容器）
useWheelTabSwitch(containerRef, (dir) => { /* dir: 1 下一个，-1 上一个 */ });
// <div ref={containerRef}>…</div>
```

- hook 内部用原生 `wheel` 监听（passive），绑在**副容器**上——标签少时整个栏目区域滚动都能切换。
- 007 测试页（test.tsx）已用此 hook 作为示范。
- 手写方式（如 DataManagerPanel 将 `handleTabWheel` 绑在面板容器 div）仍有效，但**新代码一律用 hook**，不要手写 React `onWheel`。

**技术要点：**
- 优先用**原生监听** `el.addEventListener("wheel", handler, { passive: true })`，比 React `onWheel`（合成事件）可靠，避免与 `data-tauri-drag-region` 拖拽区域冲突（TopBar/SettingsSidebar 参考实现）。
- 切换逻辑：`e.deltaY > 0` 切下一个，否则切上一个；设置面板打开时忽略（如 `isSettingsOpen()` 检查）。

**验收：** 标签只有 2-3 个时，鼠标在顶栏空白区域滚动也能切换标签；标签多到溢出时同样生效。

## 图标规范

**应用图标（app-icon.svg）：**

1. **主题关联** — 图标设计应与项目功能相关联。
2. **非板正风格** — 避免过于几何/板正的设计，使用有机/流动形态。
3. **透明/渐变背景** — 不要使用完整色块填充，使用渐变、半透明、点阵纹理。
4. **占比合理** — 图标本体应占画布（512×512）主体面积。
5. **格式** — 标准 SVG，`viewBox="0 0 512 512"`。

图标生成：`npx tauri icon -- app-icon.svg`（前提：项目根目录存在 `app-icon.svg` 源文件，如 002/003/004；框架模板不含源文件，无需重新生成）

**前端 UI 图标：**

- 统一使用行内 SVG（Lucide 风格：`stroke="currentColor" strokeWidth="2" fill="none"`）。
- 通过 CSS 变量（`var(--accent)`、`var(--text-muted)` 等）控制颜色。
- 避免使用 Unicode 符号代替图标（如 ✓、▼、⚠ 等）。
- 尺寸规范：Tab 图标 18×18，卡片图标 24×24，模式按钮图标 14×14。

## 日志级别规范

### 后端（Rust）→ 前端（TypeScript）级别映射

通过 Tauri 事件（`app.emit` 或 `UnboundedSender` 通道）传递日志到前端时，**level 字段的值必须与前端 `@appkit/ui` 的 `LogLevel` 类型保持一致**。

`@appkit/ui` 的 `LogLevel` 定义（[LogPanel.tsx](../../shared/ui/src/components/LogPanel.tsx)）：

```typescript
export type LogLevel = "info" | "success" | "error" | "warn" | "step" | "debug";
```

| 后端 emit level | 前端显示颜色 | 含义 |
|:---------------:|:-----------:|------|
| `"info"` | 灰色（默认） | 普通信息 |
| `"success"` | 绿色 | 成功完成 |
| `"error"` | 红色 | 错误 |
| `"warn"` | 黄色 | 警告 |
| `"step"` | 蓝色（accent） | 阶段步骤 |
| `"debug"` | 灰色（muted） | 调试信息 |

```rust
// ✅ 正确：使用 LogLevel 定义的级别名
emit(&progress, "success", "数据获取完成");
emit(&progress, "info", "正在连接浏览器...");
emit(&progress, "warn", "登录 cookie 过期");

// ❌ 错误：使用 LogLevel 不存在的 "ok"
emit(&progress, "ok", "数据获取完成");  // 前端显示为灰色 info
```

### 前端事件监听映射

如果后端已经使用了非标准级别名（如 "ok"），前端**必须**在 `listen` 中做映射：

```typescript
listen<{ msg: string; level: string }>(eventName, (event) => {
  const { msg, level } = event.payload;
  // 后端 "ok" → 前端 "success"
  logFn(msg, level === "ok" ? "success" : level);
});
```

### 日志事件 Payload 格式

后端发射日志事件时，payload 统一使用以下格式（`msg` 为消息文本、`level` 为日志级别；如需表格日志可附加 `headers`/`rows`，前端 LogPanel 会自动渲染为表格）：

```rust
// Rust 端
let _ = app.emit("event-name", serde_json::json!({
    "msg": "操作成功",
    "level": "success",
}));
```

前端 TypeScript 侧对应：

```typescript
// 解析 payload
const { msg, level } = event.payload as { msg: string; level: string };
```

### 新增日志发射函数

如需创建新的日志发射函数，须按以下模板：

```rust
/// 发送带级别的进度事件到前端
/// level 取值必须与 @appkit/ui 的 LogLevel 一致：
/// "info" | "success" | "error" | "warn" | "step" | "debug"
fn emit_with_level(tx: &Option<UnboundedSender<String>>, level: &str, msg: &str) {
    if let Some(tx) = tx {
        let payload = serde_json::json!({"msg": msg, "level": level});
        let _ = tx.send(payload.to_string());
    }
}

// ✅ 使用示例
emit_with_level(&progress, "success", "登录成功");
emit_with_level(&progress, "info", "正在处理...");
emit_with_level(&progress, "error", "登录失败");
```

### 常见错误

| 错误写法 | 后果 | 正确写法 |
|---------|------|---------|
| `emit(progress, "ok", msg)` | 前端显示灰色 info | `emit(progress, "success", msg)` |
| 自行发明级别名如 `"done"`、`"finished"` | 同 fallback 到 info | 使用已有的 LogLevel |
| 在前端硬编码 `level: "ok"` 传给 `log()` | 同 fallback 到 info | 使用 `level: "success"` |

## 大列表渲染规范（虚拟滚动表格）

### 适用场景

当表格数据量可能超过 **200 行** 时，**禁止一次性渲染全部 DOM 节点**，必须使用虚拟滚动（Virtual Scrolling）只渲染可视区域内的行。

> 一次性渲染全部行会导致 DOM 节点数过大，造成页面卡顿、滚动不流畅、内存占用高。

### 参考实现（007 项目）

目前没有共享的虚拟滚动表格组件，各项目按需自行实现。007 项目的实现可作为参考：

使用 `@appkit/ui` 导出的 `VirtualTable` 组件：

```typescript
import { VirtualTable } from "./ui";
import type { VirtualColumn } from "./ui";

// 定义列
const columns: VirtualColumn<RowType>[] = [
  { header: "SKU", render: r => r.SKU, style: { maxWidth: "200px" } },
  { header: "数量", render: r => r.qty, style: { textAlign: "right" } },
];

// 使用
<VirtualTable<RowType>
  rows={data}
  columns={columns}
  rowClassName={r => r.warning ? "warning-slow" : undefined}
  emptyText="暂无数据"
  listHeader={<div>标题行</div>}
/>
```

### 参数说明

| 参数 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `rows` | `T[]` | 是 | 全部数据行 |
| `columns` | `VirtualColumn<T>[]` | 是 | 列定义，每列指定 `header`、`render`、可选 `style` |
| `rowClassName` | `(row: T) => string \| undefined` | 否 | 按行数据返回 CSS 类名，用于条件染色 |
| `emptyText` | `string` | 否 | 无数据时的提示文字 |
| `listHeader` | `React.ReactNode` | 否 | 表头上方的内容，如仓库名、清除按钮等 |

### 渲染机制

- 每行固定高度 **28px**，可视区域上下各预留 **15 行** 作为滚动缓冲（OVERSCAN）
- 通过 `ResizeObserver` 自动监听容器尺寸变化
- 只渲染 `startIdx ~ endIdx` 范围内的行，其余行用空白占位 `padding` 替代
- 典型场景下 DOM 节点数从 N 万行降至 ~60 行

### 预警行染色规范

使用 CSS 类名替代行内 `style`，便于统一管理：

```css
/* 库存周转过慢（>80 天）— 浅红色 */
.warning-slow {
  background: rgba(255, 199, 206, 0.3);
}

/* 库存周转过快（<30 天）— 浅黄色 */
.warning-fast {
  background: rgba(255, 235, 156, 0.3);
}
```

```tsx
// 在 rowClassName 中返回对应的类名
rowClassName={r =>
  r.预警.includes(">80") ? "warning-slow" :
  r.预警.includes("<30") ? "warning-fast" : undefined
}
```

> **原则：** 凡需按行条件染色的，一律通过 `rowClassName` + CSS class 实现，禁止在 `render` 中写行内背景色。

### 常见错误

| 错误写法 | 问题 | 正确做法 |
|---------|------|---------|
| `rows.map(r => <tr>...</tr>)` 全量渲染 | 数据量大时卡死 | 改用虚拟滚动实现 |
| `rowClassName` 返回的类名放入 `style={}` 中 | 不生效且报错 | 作为 `<tr>` 的 `className` 属性独立设置 |
| 每个页面手写自己的虚拟滚动组件 | 重复代码、不一致 | 参考 007 项目实现 |
