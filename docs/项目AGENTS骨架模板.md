# 项目级 `AGENTS.md` 骨架模板（参考 008）

> **目的**：新项目（或老项目补全）`AGENTS.md` 时，按本骨架填。**所有项目都该遵循**这个骨架 —— AI 接手时第一件事就是读 `AGENTS.md`，结构一致才能快速定位。
>
> **标杆**：[`projects/008-紫鸟运营工具/AGENTS.md`](../../glbt-apps/projects/008-紫鸟运营工具/AGENTS.md)（**全仓唯一完整骨架示范** —— R1~R7 + AI 接手路由表 + 模块护照索引 + 文档保鲜纪律）。

## AI 上手路由表

| 我要做什么 | 读什么文件 | 关键函数 / 入口 |
|-----------|-----------|---------------|
| <动作 1> | `<文件路径>`（顶部护照） | `<函数名>()` |
| <动作 2> | `<文件路径>` + `<关联文件>` | `<函数名>` / `<常量>` |

| 排查 `<症状>` | `<文件路径>` 硬规则区 | `<节号>` |

> **填法**：每行一个高频场景。不要列所有函数 —— 只列"改了 80% 的工作都会碰到的"。

| # | 规则 | 违反后果 | 来源 |
|---|------|---------|------|
| R1 | <规则 1> | <症状> | <踩坑记录 / docs/某文件 §X> |
| R2 | <规则 2> | <症状> | <来源> |
| ... | ... | ... | ... |

> **填法**：
> - 规则从"踩坑记录"里提炼，每条必须有**现象 → 根因 → 来源**三件套

> - **不**要写"注意 xxx"、"小心 yyy"这类无来源的口号 —— 那是无效规则

## 模块护照索引

以下核心模块顶部均有「模块护照」（JSDoc 块），改代码必须同步更新护照：

| 文件 | 护照状态 |
|------|---------|
| `<path/to/core-module.ts>` | ✅ 已有（约 X 行核心）|
| `<path/to/another-module.ts>` | ⚠️ 需补（见模板） |
| ... | ... |

> **护照模板**（贴在每个核心模块顶部）：

```ts
/**
 * @responsibility  <本模块职责（一句话）>
 * @hard-rules      <引用的硬规则编号，如 R1, R3>
 * @接口清单       <关键函数名 / 类型名 / 命令名>
 * @状态           <真机验证日期 + 结果，如 "2026-09-20 在 008 dev 跑通">
 */
```

> **填法**：护照状态 `✅` 表示顶部已有完整 JSDoc；`⚠️` 表示需补。改代码前**先读 passport**，改完**同步更新**。

## 文档保鲜纪律

1. **改核心模块必须同步更新该模块顶部的模块护照**（增删接口、改规则、修 bug 都算）。护照过时视为代码未完成。
2. **新踩坑先记入 `docs/<项目>-踩坑.md`**，已沉淀为硬规则的从踩坑记录删除，只留规则表引用。
3. **待办清单已完成项超过 3 天**，只保留一行摘要 + commit hash，详情见 git log。
4. **路由表 / 硬规则速查变化时**，同步更新本文件（这是 AI 每次必读的入口）。
5. **文档与代码冲突时，以代码为准**，并修正文档。

## 怎么用这个模板

### 场景 A：新项目从 000 复制

1. 复制模板到 `projects/XXX-你的项目名/AGENTS.md`
2. 把 `<!-- XXX -->` 占位符删掉，按项目实情填实
3. **第一周**不必填硬规则 / 模块护照（项目刚起步，没坑）—— 但**第一节"第一件事"+ AI 上手路由表**必须有
4. 项目有第一个真实 bug / 第一个真实功能后，回来补 R1

### 场景 B：老项目补全（19 个空壳项目）

1. 不要一次性写完所有节 —— **先写"## 这是什么"和"## 纪律"**（已具备）
2. **加一节"## 状态"** —— 注明"有源码无 docs/，业务背景问用户"
3. 第一个真踩坑后加 R1，逐步加 R2、R3…
4. 半年后模块稳定了再补"模块护照索引"

### 场景 C：模块顶部加 JSDoc 护照

参考 008 现有模块（`weekly-data-multi-site.ts` 顶部那段）。**改了 passport 必须改对应 R 表**。

## 为什么 008 是标杆

008 的 AGENTS.md（3692 字节，全仓最大）覆盖：
- ✅ 第一件事：必读文档清单
- ✅ AI 上手路由表：7 个高频场景
- ✅ 硬规则速查：R1~R7（每条都有现象/根因/来源）
- ✅ 模块护照索引：8 个核心文件，标 ✅/⚠️
- ✅ 文档保鲜纪律：5 条纪律
- ✅ 纪律：引用全局 + 项目特有

**其它 19 个项目**多数只有"## 这是什么 + ## 纪律"两段式空壳。**填补方向**：
- 项目熟手按节奏补"路由表 + R 表"
- 模块稳定后补"护照索引"

不要等"全填完"再行动 —— **每周加一条 R 比半年一次填 8 条好**。

## 反模式（不要这样做）

| 反模式 | 后果 |
|---|---|
| AGENTS.md 通篇"待补"、"TODO" | AI 接手 = 没线索 = 反复试错（= 这次 000 复发） |
| 硬规则只写"小心 xxx"没来源 | 规则不可验证，违反无后果 |
| 路由表 30 行全列每个函数 | 失去筛选意义，AI 反而慢 |
| 文档过期不更新 | "以代码为准"原则失效，AI 信任 AGENTS.md 但被骗 |
| 模块护照纯注释从不改 | 护照与代码脱节，违背保鲜纪律 |
