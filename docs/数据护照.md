# 数据护照（Data Passport）— 框架层数据交互规范

> **目的**：让新 AI 第一句话就知道「每个数据点的用途 / 谁在用 / 改它会怎样」，防止「做完就忘」。

> **同步入口**：`glbt-apps/docs/新AI上手.md` 第 1.4 节指向本文件；所有项目 AGENTS.md「第一件事」必须先读本文件。

## 1. 护照格式

每个**跨页面 / 跨模块**使用的数据点必须有「数据护照」。覆盖三类数据：

| 数据类型 | 标识 | 示例 |
|---|---|---|
| **localStorage key** | `@type localStorage` | `platform-profile-shopee1` |
| **invoke 命令** | `@type invoke` | `start_temu_browser` |
| **Tauri State / 共享状态** | `@type state` | `GlobalBrowserCache` |

### 1.1 TypeScript / TSX 注释模板（localStorage key）

```typescript
/**
 * @data-passport
 * @key platform-profile-{PlatformKey}            ← 数据点 ID（必须唯一）
 * @type localStorage                              ← 数据类型
 * @category config                                ← config / preference / record / cache
 * @responsibility 绑定平台主体到紫鸟环境           ← 一句话讲清职责（< 60 字）
 * @written-by automation-settings.tsx (useBoundShop)
 * @read-by [homepage, shopee.tsx, temu.tsx, schedule.tsx, test.tsx] 经 useBoundShop
 * @format 三段式 "bt|userDataDir|profileId"      ← 数据形态（parseBoundKey 拆）
 * @hard-rules
 *   R1: 业务页禁止用 useBrowserBaseData 查（空缓存）
 *   R2: 改 key 必须三段式同步：read / write / parseBoundKey
 * @deletion-impact 4 UI 页面同步空状态；用户重新绑定前不可用
 * @since 2026-09
 * @see [use-bound-shop.ts:106-141] 实现
 */
```

### 1.2 Rust 注释模板（invoke 命令）

```rust
/**
 * @data-passport
 * @key start_temu_browser                         ← 命令名（与 #[tauri::command] 名一致）
 * @type invoke                                    ← 数据类型
 * @category automation                            ← config / automation / record / cache
 * @responsibility 启动 Edge/Chrome + 等 CDP 端口就绪 + 返回 port
 * @called-by [src/withdraw-temu.ts, src/components/temu.tsx, src/components/schedule.tsx, src/components/test.tsx]
 * @returns { port: u16, wsUrl: String, profile: String }
 * @hard-rules
 *   R1: 必须走 BrowserInstance::start_or_connect（不能直 spawn）
 *   R2: detach() 替代 std::mem::forget（防 Drop 时 kill 进程）
 * @deletion-impact 前端 4 个页面「▶ 立即提现」按钮失效；Rust 端所有 Temu 业务命令断流
 * @since 2026-09
 * @see [shared/automation/src/browser.rs:129-296] BrowserInstance::start_or_connect
 */
```

### 1.3 必备字段（最少 6 个，少一个就 fail）

| 字段 | 必填 | 说明 |
|---|---|---|
| `@key` | ✅ | 数据点唯一 ID |
| `@type` | ✅ | `localStorage` / `invoke` / `state` |
| `@category` | ✅ | `config` / `preference` / `record` / `cache` / `automation` |
| `@responsibility` | ✅ | 一句话讲清职责 |
| `@written-by` 或 `@called-by` | ✅ | 谁会写 / 谁会调 |
| `@deletion-impact` | ✅ | 删了/改了会怎样（强制 AI 思考副作用） |
| `@hard-rules` | 推荐 | 引用项目 AGENTS.md 的硬规则编号 |
| `@since` | 推荐 | 引入日期 |

## 2. 强制机制（多管齐下防"AI 做完就忘"）

### 2.1 校验脚本（每次 commit 必跑）

```bash
# 跨仓扫描所有 useData / invoke / State 注入点
node my-skills/scripts/passport-scan.mjs scan <项目路径>

# 校验护照完整性（缺字段就 fail）
node my-skills/scripts/passport-scan.mjs check <项目路径>

# 自动生成护照初版（给已有数据点补 @data-passport 模板）
node my-skills/scripts/passport-scan.mjs generate <项目路径>
```

**强制项**（passport-scan check 必检）：

1. 每个 `useData({ key: 'xxx' })` 调用点上方必须有 `@key xxx` 的 `@data-passport` 块
2. 每个 `invoke("xxx")` 调用点对应的 Rust `#[tauri::command]` 函数必须有护照
3. 每个 `tauri::State<T>` 注入的 State 类型必须有护照（type-level）
4. 缺 `@responsibility` / `@deletion-impact` 等必备字段 → **fail**
5. `@key` 与实际 `useData({ key })` 或 `invoke("xxx")` 不一致 → **fail**

### 2.2 pre-commit 钩子（自动）

```
[my-skills] 已配 `.git/hooks/pre-commit`：
  - 扫 staged diff
  - 新增 useData / invoke 调用点 → 必须含 @data-passport 注释
  - passport-scan check 失败 → 阻止 commit
```

如需绕过（紧急 fix）：`git commit --no-verify`，但必须在 commit message 写明 `bypass-passport-check: <理由>`。

### 2.3 AI 接手流程（硬约束）

各项目 AGENTS.md「第一件事」必须按以下顺序：

```
1. 读 app-kit/docs/数据护照.md（本文件）        ← 知道有哪些数据 + 谁在用
2. 读 app-kit/docs/框架接口清单.md §11 场景化 API  ← 知道怎么用 framework
3. 读 app-kit/docs/框架接入指南.md              ← 知道新项目怎么接入
4. 读项目 docs/新AI上手.md                      ← 项目级纪律
```

**新写代码前必读**：任何 `useData({ key })` / `invoke("xxx")` / `tauri::State<T>` 调用，**先 grep 数据护照**：

```bash
# 看到 platform-profile-shopee1 第一反应：
node my-skills/scripts/passport-scan.mjs show platform-profile-shopee1
```

## 4. 改现有数据点的同步规则

**改 key / 改格式 / 加 reader / 改字段含义**时，必须**三处同步**：

| 改动 | 必须同步 |
|---|---|
| 改 key 名 | ① useData 调用点 ② 注释护照 ③ docs/新AI上手.md 速查表 |
| 改数据格式（如三段式 → JSON） | ① parseBoundKey ② writer ③ reader ④ 注释护照 `@format` |
| 加新 reader | ① useBoundShop（或类似 hook） ② reader 文件顶部加 `@read-by` ③ 注释护照 |
| 删除数据点 | ① 删 useData / invoke ② 注释护照标 `@deprecated since YYYY-MM` 保留 6 个月 ③ docs/新AI上手.md 速查表 |

**违反任一同步** = 数据不一致 bug + AI 接手时无法 grep 到正确信息。

## 6. 反模式（不要这样做）

### ❌ 反模式 1：业务页用 `useBrowserBaseData` 查紫鸟店铺

```typescript
// ❌ 业务页用 useBrowserBaseData 查紫鸟店铺 → 空缓存误报未绑定
const { browsers } = useBrowserBaseData();
const ziniao = browsers.find(b => b.userDataDir === ...);

// ✅ 直接读 localStorage（useBoundShop 已封装）
const { bound } = useBoundShop("shopee1");
```

**根因**：业务页挂载不触发检测，`browsers` 是空数组。详见 `glbt-apps/docs/踩坑记录-业务.md` 2026-09-14。

### ❌ 反模式 2：自拼"开店铺"4 步

```typescript
// ❌ 自己拼：agent status → startBrowser → 轮询 → enterShopPoll
const st = await ziniaoAgentStatus();
// ... 60s 轮询 ...
const cdp = await ziniaoAgentCdpPort(browserId);
// ...

// ✅ framework 一行调（已封装缓存 + discover + wait_ready）
const (browser, tab) = await getOrOpenZiniaoShop(agentPort, browserId);
```

**根因**：散落各模块，AI 漏步骤或用老接口。详见 `glbt-apps/platforms/ziniao/src/manager/get_or_open.rs`。

### ❌ 反模式 3：用 `BrowserInstance::connect`（已 deprecated）

```typescript
// ❌ 老 connect（8~12s 重试 × 30 次）
const browser = await BrowserInstance::connect("127.0.0.1", port);

// ✅ connect_fast（已开店铺 < 500ms）
const browser = await BrowserInstance::connectFast("127.0.0.1", port);

// ✅ connect_with_retry（冷启动竞态场景）
const browser = await BrowserInstance::connectWithRetry("127.0.0.1", port, 30);
```

详见 `shared/automation/src/browser.rs:305-313`。

### ❌ 反模式 4：framework 顶层 API（race bug）

```typescript
// ❌ 顶层 API 有 race（spawn 后立即返回 port，无 wait）
debugLaunchProfileSmart(...);

// ✅ 完整路径（framework 已 wait 端口 15s）
BrowserInstance::start_or_connect(...);
```

详见 `glbt-apps/projects/016-自动提现/AGENTS.md §已知坑 #3`。

### ❌ 反模式 5：不填护照就 commit

```typescript
// ❌ 新加 useData({ key: 'xxx' }) 没填 @data-passport 注释
const [value] = useData({ key: 'new-feature-xxx', ... });

// ✅ 顶部加 @data-passport 注释（最少 6 个字段）
/**
 * @data-passport
 * @key new-feature-xxx
 * @type localStorage
 * @category config
 * @responsibility 新功能配置项
 * @written-by xxx
 * @deletion-impact ...
 */
const [value] = useData({ key: 'new-feature-xxx', ... });
```

pre-commit 钩子会扫新增调用点，没填护照就 **fail**。

## 7. 排错

| 现象 | 排查命令 |
|---|---|
| "数据点不存在" / 拿到空值 | `passport-scan show <key>` 看是否在索引里 |
| "新 AI 不知道这个 key 干嘛的" | 强制新 AI 先 `passport-scan show <key>` 再写代码 |
| "改了 key 老数据丢失" | 看护照 `@format` 字段，parse 函数是否同步改 |
| "pre-commit 失败说缺护照" | `passport-scan generate <项目路径>` 自动补护照初版 |
| "passport-scan check 误报" | 看 `@key` 与 `useData({ key })` / `invoke("xxx")` 是否完全一致（含大小写） |
