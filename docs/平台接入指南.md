# 平台接入指南（新项目接入浏览器能力全景）

> **本文件解决**：新项目（020 / 021 / ...）从 000 复制后，**如何接入浏览器能力**。覆盖：
> 1. 内置浏览器（Edge / Chrome）— 不需要任何注册
> 2. 紫鸟 / 易得客 — Rust 端有 `registry::register()` + 前端有一站式注册
> 3. 店小秘 / Temu / 海多客 / 多维表格 — Rust 端**没有 detector**（不参与 `detect_browsers`），但**前端公共测试面板齐备**
> 4. 马帮 / 百世 / 元仓 / popup — Rust 端有 crate，无前端公共组件
>
> **同步文档**：
> - 紫鸟专项（最复杂）：[`app-kit/docs/框架接入指南.md`](./框架接入指南.md)（6 步骨架）+ [`glbt-apps/shared/ui-biz/README.md`](../../glbt-apps/shared/ui-biz/README.md)（一站式注册）
> - 平台 × 命令 × 项目登记表：[`glbt-apps/shared/ui-biz/src/components/platform-test/registry.ts`](../../glbt-apps/shared/ui-biz/src/components/platform-test/registry.ts)
> - 项目级 AGENTS 骨架：[`app-kit/docs/项目AGENTS骨架模板.md`](./项目AGENTS骨架模板.md)

## 一、内置 vs 注册：4 种浏览器接入模式

新项目想"接入浏览器"，先问自己**要的是哪种能力**：

| 模式 | 例子 | 你要的"接入"是什么 |
|---|---|---|
| **M1 内置** | Edge / Chrome | **什么都不用做**——`detect_browsers` 自动返回，前端自动检测到 |
| **M2 检测 + 命令** | 紫鸟 / 易得客 | Rust 端调 `registry::register()` + 前端调 `registerZiniaoFramework()`（或易得客的浏览器适配器） |
| **M3 仅命令** | 店小秘 / Temu / 海多客 / 多维表格 | Rust 端不调 detector（**前端无该平台"全局浏览器配置"卡片**）；只 Cargo 引用 + `build.rs` 注册平台命令 + 前端用公共测试面板 |
| **M4 业务 crate** | 马帮 / 百世 / 元仓 / popup | Rust 端提供业务命令；前端无公共 UI；项目自己写 |

> **新项目典型组合**（按业务）：M1（用户 PC 必装）+ M2（紫鸟业务）+ M3（多维表格等业务数据源）。**不写 Rust 端 detector 不会让 M3 失败**——M3 本来就没"全局浏览器配置"概念。

## 二、M1：Edge / Chrome 内置（不需要任何注册）

**事实**：`app-kit/shared/core/src/browser/browser_paths.rs` 写死了 `detect_edge()` / `detect_chrome()`，**框架侧自动注入**。

**新项目要做的**：
- ✅ 0 行代码
- ❌ **不要**尝试"注册 Edge"——`register_browser_detector("edge", ...)` 会失败（id 已存在）
- 前端 `BrowserConfigPanel` 自动显示 Edge / Chrome 卡片

**会再踩的坑**：
- ❌ AI 误以为需要 `appkit-core` feature gate 才能启用 ——**不用**，cmd-browser feature 默认就包含

## 三、M2：紫鸟 / 易得客（检测 + 33+ 命令 + 前端 UI 扩展）

### 3.1 紫鸟 6 步骨架

**完整 6 步** 见 [`app-kit/docs/框架接入指南.md`](./框架接入指南.md)（含 `package.json` / `main.tsx` / `vite-env.d.ts` / `Cargo.toml` / `lib.rs` 全套）。**核心是 `registerZiniaoFramework()` 一站式注册 4 项**（不是 `registerZiniaoUIExtension()` 单项）。

### 3.2 紫鸟"店铺头像"问题的真相

**反复被问到**："紫鸟店铺头像呢？" —— **紫鸟浏览器本地 / agent 接口都没有真实店铺头像**。**正确做法是：紫鸟 agent 返回的 `platform_name`（TikTok Shop / Shopee / Ozon）→ `@glbt/ui` 的 `platformAvatarDataUri()` → 品牌 SVG 头像**。

证据链：
1. [`glbt-apps/platforms/ziniao/src/registry.rs`](../../glbt-apps/platforms/ziniao/src/registry.rs) L183-188 Rust 注释写明：店铺 `avatar_base64` **显式置空**（避免显示 Chrome 默认预设头像误导）
2. [`glbt-apps/shared/ui-biz/src/utils/platform-avatars.ts`](../../glbt-apps/shared/ui-biz/src/utils/platform-avatars.ts) 内嵌 TikTok / Shopee / Ozon 品牌 SVG（官方原样）
3. [`glbt-apps/shared/ui-biz/src/utils/ziniao-env-map.ts`](../../glbt-apps/shared/ui-biz/src/utils/ziniao-env-map.ts) `applyZiniaoEnvNames` L56-60 在写入店名时**同时**调用 `platformAvatarDataUri()` 写入 `avatar_base64`

**首次接入会看到的现象**（不是 bug）：
- 全局浏览器配置里紫鸟店铺卡片**显示首字母占位**（不是品牌 SVG）
- **未点"登录并绑定店铺名称"之前**就是这样——`core-ziniao-env-map` 是空的，`applyZiniaoEnvNames` 直接返回原 profile
- **点完绑定 + 同步店铺名称**之后：店名变真实店名 + 头像变品牌 SVG（如果 platform_name 命中 TikTok/Shopee/Ozon）

**会再踩的坑**（必看）：
| 坑 | 原因 |
|---|---|
| "店铺头像没出来" | 未点"登录并绑定店铺名称"；或 `registerZiniaoFramework()` 没调导致 `applyZiniaoEnvNames` 没注册 |
| 店名 + 头像同时消失 | 同一个根因：transform 没注册（绑定时写入 localStorage，但检测时不应用）|
| 想加新平台品牌 SVG | 加 `platform-avatars.ts` 的 `PLATFORM_AVATARS` 数组（业务侧资产，框架不动）|

### 3.3 易得客（edecker）

- Rust 端：`platform_edecker::registry::register()`（在 `.setup` 块调）
- 前端：**没有"一站式"注册**。**业务侧**易得客店铺用 `children` 模型展示（不参与紫鸟的 `core-ziniao-env-map` 流程）
- 项目侧 hook：`children` 数组就是 edecker BrowserInfo 的子项，前端用 `BrowserConfigPanel` 自动渲染

## 四、M3：店小秘 / Temu / 海多客 / 多维表格（仅命令 + 前端公共 UI）

**关键事实**：这 4 个平台 **Rust 端没有 `registry.rs`**（不参与 `detect_browsers`），但 **`@glbt/ui` 提供完整前端公共测试面板**：

| 平台 | API 层（`@glbt/ui`）| 测试面板（`@glbt/ui`）| 命令清单 | 哪些项目用 |
|---|---|---|---|---|
| **店小秘** | `dxm-api.ts` | `DxmTestPanel` | `PLATFORM_TEST_REGISTRY` dianxiaomi 段 | 001 / 003 / 004 / 006 / 010 |
| **Temu** | `temu-api.ts` | `TemuTestPanel` | temu 段 | 002 / 003 / 013 |
| **海多客** | `haiduoke-api.ts` | `HaiduokeTestPanel` | haiduoke 段 | 006 / 007 |
| **多维表格** | `kdocs-api.ts` | `KdocsTestPanel` | kdocs 段 | 003 / 006 / 007 |

完整登记表：[`glbt-apps/shared/ui-biz/src/components/platform-test/registry.ts`](../../glbt-apps/shared/ui-biz/src/components/platform-test/registry.ts)

### 4.1 新项目接入 M3 平台的步骤

如果新项目（如 020）要用**店小秘** + **Temu** 做业务，**不要"先复制 008"**（会带一堆紫鸟业务面板），而是按 6 步骨架接：

1. **`Cargo.toml` 加依赖**：
   ```toml
   platform-dianxiaomi = { path = "../../../platforms/dianxiaomi" }
   platform-temu = { path = "../../../platforms/temu" }
   ```
   （**不要加** `features = ["plugin"]` —— 这 4 个平台没有 `plugin.rs`，加了就编译失败）

2. **`lib.rs` `.setup` 块**：**不调** `registry::register()`（没有）。**只调** `appkit_core::tauri_bridge::init()` 的 `.plugin(...)`

3. **`build.rs` `InlinedPlugin::commands(&[...])`**：注册平台命令的**裸名**（不带 plugin 前缀）。完整清单见 `PLATFORM_TEST_REGISTRY` 对应段。例如店小秘要注册 `save_dxm_credentials` / `load_dxm_credentials` / `ensure_browser_dianxiaomi` 等 14 条

5. **`App.tsx` 测试 tab**：用 `<DxmTestPanel platformKey="dianxiaomi" .../>` / `<TemuTestPanel platform="gz" .../>` 等公共组件
   - props 按组件签名传（具体看 `components/platform-test/*.tsx`）
   - 私有业务（如 003 的备货数据）经 `extraSections` 注入

### 4.2 会再踩的坑

| 坑 | 原因 | 修法 |
|---|---|---|
| typecheck 找不到 `DxmTestPanel` / `TemuTestPanel` | `@glbt/ui` 没正确装或没 import | `package.json` 加 `"@glbt/ui": "workspace:*"` + 跟紫鸟一样 `import "@glbt/ui/styles"` |
| Rust 编译 `cannot find function 'commands'` | 加了 `features = ["plugin"]`（紫鸟专属）| **去掉**，M3 平台不带 plugin feature |
| 业务命令 not found | `build.rs` 没在 `InlinedPlugin::commands(&[...])` 列出 | 复制 `PLATFORM_TEST_REGISTRY` 对应平台的命令裸名 |
| 测试面板点了没反应 | 命令参数签名不对 | 公共命令参数对齐 003 / 007 实现（见 registry 的 `note` 字段）|
| "全局浏览器配置"看不到店小秘 | **正常的**——M3 平台不参与 `detect_browsers` | 不修；如果业务需要看到店小秘，需要走 M2 模式（不推荐）|

## 六、020 项目（edge+紫鸟）实际接入清单

假设**新项目 020-xxx-浏览器混合**需要"Edge（内置）+ 紫鸟业务"：

| 步骤 | 怎么做 | 备注 |
|---|---|---|
| 1. 复制 000-基础模板 | `xcopy /E /I "projects\000-基础模板" "projects\020-xxx"` | |
| 2. `package.json` 加依赖 | `"@glbt/ui": "workspace:*"` | 必须 |
| 3. `main.tsx` 加紫鸟一站式注册 | `import "@glbt/ui/styles"` + `registerZiniaoFramework()` | 一站式 4 项，别只调单项 |
| 4. `vite-env.d.ts` declare | `declare module "@glbt/ui/styles"` | 必须 |
| 5. `Cargo.toml` 紫鸟依赖 | `platform-ziniao = { ..., features = ["plugin"] }` | **紫鸟专属 plugin feature** |
| 6. `lib.rs .setup` 加 detector | `platform_ziniao::registry::register()` | Edge 是内置的**不需要**这一步 |
| 7. `lib.rs .invoke_handler` | `.invoke_handler(platform_ziniao::plugin::commands())` | 33 条紫鸟命令 |
| 8. `pnpm install` | | 物化 `@glbt/ui` 副本 |
| 9. `pnpm typecheck` | 必须 0 错 | |
| 10. 启动 + 验证 | 进"全局浏览器配置"应看到 Edge / Chrome / 紫鸟 三张卡片；点开紫鸟展开有「登录并绑定店铺名称」按钮 | |

**不会再踩的坑**：
- ✅ Edge 不需要注册（内置）
- ✅ 紫鸟店名 / 头像绑定后能正常显示（`applyZiniaoEnvNames` 在 transform 链里）
- ✅ 紫鸟形状圆角矩形（`avatarShape: "rounded"`）
- ✅ 紫鸟 CDP 补丁卡（`ZiniaoPatchCard`）

**还会踩的坑**（已知 + 已记录）：
- ⚠️ 用户首次启动看到的是占位首字母，不是品牌 SVG（必须先点"登录并绑定店铺名称"）
- ⚠️ `core-ziniao-env-map` 数据项没在 `data.ts` 重复声明（`@glbt/ui` 的 `registerZiniaoFramework()` 已经声明过了）

## 七、`PLATFORM_TEST_REGISTRY` 的地位

[`glbt-apps/shared/ui-biz/src/components/platform-test/registry.ts`](../../glbt-apps/shared/ui-biz/src/components/platform-test/registry.ts) 是**全仓唯一的"平台 × 命令 × 项目使用情况"登记表**。

**地位**：
- AI 接手时**先查它**——知道哪些平台有公共组件、哪些命令已对齐公共契约、哪些项目已接入
- Rust 端 `build.rs` 的命令白名单**直接抄它**——避免遗漏
- 业务命令迁移到公共层时**更新它**——`note` 字段记录迁移进度

**使用方式**（伪代码）：
```bash
# 接入新平台 X 前先查：
grep -A 5 "key: \"X\"" glbt-apps/shared/ui-biz/src/components/platform-test/registry.ts
# 看 commands / note 决定 build.rs 列表 + extraSections 注入点
```

## 附录：本指南的来源

2026-09 期间，因 000 模板反复试错与"新项目（edge+紫鸟）还会踩什么"反思，系统性梳理 GLBT-gz 浏览器接入的 4 层架构 + 5 平台对比 + 4 模式分类。**澄清了三个被反复误解的事实**：

1. **紫鸟"店铺头像"不存在** —— 真实答案是 platform_name → 品牌 SVG
3. **Edge / Chrome 是框架内置** —— 不是注册式，新项目不要去"注册 Edge"
4. **M3 平台（店小秘/Temu 等）不参与 `detect_browsers`** —— "全局浏览器配置"看不到店小秘是正常的

未来任何新项目接入浏览器能力，**先按本文 M1~M4 分类**确认要走哪种模式，再跟 `PLATFORM_TEST_REGISTRY` 对齐命令清单，最后按各模式的具体步骤接入。
